# 작업 관리_협업 방식과 회고

## ● 회의와 발표 피드백 정리

프로젝트 매니징을 맡아 Confluence에 기초 기획, 역할 분담, 회의록과 발표 피드백을 모았습니다.<br>질문과 답변을 함께 남겨, 이후 작업에서 결정의 배경을 다시 확인할 수 있도록 정리했습니다.

| 정리한 자료 | 구성한 내용 |
| --- | --- |
| 회의록 | 담당자와 질문자, 질문과 답변, 작성자 메모 |
| 다른 팀의 발표 자료 | 팀별 게임 개요, 발표 흐름에 따른 슬라이드와 설명 |
| 우리 팀의 발표 피드백 | 발표 자료와 받은 질문과 피드백을 한 문서에 정리 |

## ● 구현 작업의 통합 방식

- **작업자:** 개인 브랜치에서 구현과 동작 확인을 마친 뒤, Unity 패키지와 적용 문서를 전달했습니다.
- **인계 내용:** 필요한 컴포넌트와 연결 조건, 확인한 동작과 남은 작업을 기록했습니다.
- **통합 담당자:** 전달받은 패키지와 적용 문서를 기준으로 프로젝트에 반영하도록 역할을 나눴습니다.

## ● 회고와 이후 적용

| 겪은 문제 | 배운 점과 이후 적용 |
| --- | --- |
| 모션 후보의 비교 조건이 달라 선택 기준이 흐려짐 | 속도와 하체처럼 유지할 조건을 먼저 정하고, 팔 궤적과 무릎 높이처럼 바꿀 부분을 구체적으로 전달했습니다. |
| Blender에서 다듬은 자세가 Unity에서 달라짐 | 제작 완료와 게임 적용 완료를 구분했습니다. 적용 후 자세와 동작 전환을 확인하고, 그 결과를 인계 문서에 포함했습니다. |
