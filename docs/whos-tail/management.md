# 작업 관리_협업 방식과 회고

## 팀의 협업 방식 — Confluence의 기획 기준과 Jira의 작업 일정

### 기획과 제작 기준을 찾을 수 있도록 문서를 분류

팀 Confluence는 프로젝트 개요, 기획, 제작 가이드, 스크럼 기록, 릴리스로 나뉘어 있습니다. 팀원이 담당한 이벤트 기획서에는 변경 날짜와 이유, 담당자, Jira 에픽 분류, 현재 작업 단계가 함께 적혀 있습니다. 당시 문서에서는 운영 규칙 정리 완료와 레벨 디자인 연동 대기를 구분해, 정해진 내용과 후속 작업이 필요한 부분을 확인할 수 있습니다.

### 필요한 리소스와 다음 작업을 구분

이벤트 기획서의 작업 범위는 기능별 요소와 필요 리소스로 나뉩니다. 전화부스 항목에는 모델, 문 개폐, 인원 확인, 출입 제어, 정보 선택 UI가 묶여 있고, 고블린 보상은 아이템 담당 문서를 참조합니다. 스폰 후보 위치도 배치된 상태와 최종 위치 선정, 폐쇄 일정 검토가 남은 상태로 구분되어 있습니다.

### Jira에는 실행할 작업과 일정, Confluence에는 판단 근거

팀에서는 Jira를 할 일과 일정 관리에, Confluence를 기획서와 변경 근거 정리에 사용했습니다. UI 담당 팀원이 정한 작업 규칙에서는 작업별 Jira 이슈에 시작일, 기한, 상태, 담당자와 UI 레이블을 기록하고 단계를 하위 작업으로 나눕니다. Confluence의 UI 담당 팀원 기획서 아래에는 요청, 판단, 구현, 검증, 확정 과정을 기록하도록 되어 있습니다.

## 회고 — 비교 조건을 고정하고, 게임에서 결과를 확인했습니다

모션 후보마다 속도와 하체 움직임이 달라, 바꾸려던 팔 자세를 비교하기 어려웠습니다. 이를 해결하기 위해 유지할 조건과 수정할 부위를 먼저 나누고, 팔 궤적과 무릎 높이처럼 바꿀 부분을 구체적으로 지정했습니다. 꼬리 잡기에서는 오른팔의 움직임만 수정하고, 비교한 자세에서 몸통과 다른 팔다리가 유지된 것을 확인했습니다.

Blender에서 선택한 자세가 Unity에서 다르게 보이는 문제도 있었습니다. Humanoid 리타게팅 설정을 점검한 뒤 같은 골격의 모션을 Generic 설정으로 가져오고, 기존 캐릭터 제어를 유지하면서 별도 리그의 자세를 전달하도록 연결했습니다. 그 결과 비교한 주요 자세가 Blender 시안과 같은 모습으로 표시되는 것을 확인했습니다. 이 경험을 통해 제작 화면의 완성도뿐 아니라 실제 게임에서의 적용 결과까지 확인하는 기준을 갖게 되었습니다.
