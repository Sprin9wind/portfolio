검증 목적과 범위

꼬리에 접근했을 때 대결이 시작되고, 거리나 방향이 맞지 않거나 제한 조건에 해당하면 시작되지 않는지 확인했습니다. 잡기 동작 접수와 대결 진입을 분리해 기록했습니다. 동작이 재생된 것만으로 꼬리를 잡았다고 판단하지 않았습니다.

두 캐릭터의 실제 프리팹과 꼬리 판정을 사용한 격리 테스트, 실제 맵의 오프라인 연습 모드를 확인했습니다. AI가 반복 실행과 기록을 맡고, Orca에서 실행과 독립 검토를 나눠 로그와 실제 화면을 대조했습니다.

대상: 기존 꼬리 선분 판정과 거리, 후방 각도, 시선, 상태 제한. 꼬리 형태를 따르는 판정과 두께 보정은 이전 구현 이력입니다.

테스트 방법과 기대값 대조

위치와 상태를 설정한 뒤 조건 하나씩을 바꿨습니다. 두 캐릭터 × 조건별 2회 실행하며 잡기 동작, 대결 진입, 이동 속도를 기록했습니다. 격리 테스트는 실제 잡기 함수와 지연 접촉 경로를 사용했고, 실제 맵에서는 입력 시스템에 마우스와 C/V 이벤트를 전달했습니다.

표 2. 게임 기능 변경 없이 검증 조건을 바로잡은 과정
단계근거와 조치
초기 8회 / 제외이동 조건 입증 불가대결은 시작됐지만 기록된 이동 속도(PlanarSpeed)는 모두 0이었습니다. 달리기 잡기 모션의 슬라이드 이동이 있어도, 요청한 걷기와 달리기가 입력대로 수행됐다는 근거가 될 수 없어 이동 검증에서 제외했습니다.
입력 시점 수정에디터 갱신 시점과 게임의 입력 처리 시점이 맞지 않았습니다. 테스트 입력 공급을 Unity 입력 처리 직후(InputSystem.onAfterUpdate)로 옮겼습니다.
재검증 8회 / 채택이동과 판정을 함께 확인같은 캐릭터와 초기 간격, 걷기 및 달리기 조건으로 다시 실행했습니다. 약 3.5m/s와 6m/s, 위치 변화와 대결 진입 8회를 확인했습니다.

개선된 것은 테스트의 유효성입니다. 이번 실행에서 새 제품 버그를 찾거나 게임 판정을 수정한 것은 아닙니다.

실제 화면과 맵 입력 확인

실제 맵에서는 지정된 상대와 캐릭터 간 간격을 설정하고 마우스 입력을 자동 전달했습니다. 잡기 준비 상태를 기다린 뒤 범위 밖과 안을 확인하고, 대결에 진입한 후 C, V, C, V를 입력했습니다.

유지 판단과 검증 한계

검사한 조건에서 현재 규칙과 어긋나는 판정이 재현되지 않아 사거리와 두께 보정값을 유지했습니다. 이동 테스트의 입력 방식을 수정해, 설정값과 실제 관찰값을 함께 남길 수 있게 했습니다.

확인 범위는 로컬 자동 테스트와 실제 맵의 오프라인 연습 모드입니다. 위치와 입력을 자동화했습니다. 서로 다른 속도의 추격, 온라인 지연과 여러 PC의 Shared 동작, 사용자의 직접 플레이를 통한 조작감과 재미는 검증하지 않았습니다.

추가 이동 경계 20회는 판정 직전 표본과 실제 접촉 순간의 차이가 있어 이 보고서의 동일 조건 반복 결과나 성공률로 사용하지 않았습니다.
