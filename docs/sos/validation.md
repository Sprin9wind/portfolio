# 3.1 수치 검증 계획

## 확인할 설계 가설

**약점을 빠르게 알아내 처치한 전투가, 무작위 공격을 반복한 전투보다 수명 손익이 좋아야 한다.**

| 통제할 조건 | 비교할 조건 | 기록할 결과 |
|---|---|---|
| 같은 몬스터와 개체 레벨 | 커맨드 미공략 / 공략 | 전투 시간, 플레이어 수명 소모, 흡수량 |
| 같은 공격력과 방어력 | ATBSpeed 변경 | 충전 시간, 행동 횟수, 수명 손익 |
| 같은 커맨드와 적 스탯 | 약점 파악 미사용 / 사용 | 힌트 비용, 처치 시간 단축분 |
| 같은 등급과 레벨 | 상태이상 유무 | 행동 지연, 피해 누적, 최종 손익 |

수명 손익 = 흡수한 수명 − 플레이어의 시간 소모 − 긴급 행동 비용. 비교 시 같은 단위를 사용한다. 등급별 합격 수치와 반복 횟수는 아직 정하지 않았으며, 실측 결과를 확보한 뒤 기준표에 반영한다.

## 비교를 시작하기 전

- 현재 시뮬레이터에서는 상태이상 효과를 비교할 수 없다. 지속 턴, 갱신, 중첩 규칙을 구현한 뒤 비교한다.
- 커맨드 성공 이력이 남아 있으면 이후 공격에도 ×5가 적용된다. 반복 보상의 허용 범위를 정하고 판정을 반영한 뒤 공략 유무를 비교한다.
- 수명 단위, LIFE_DECAY, 긴급 행동 비용을 하나의 기준표로 통일한다.
- 적의 공격 패턴은 무작위로 실행된다. 반복 횟수를 정하고 패턴 선택 이력을 함께 기록한다.

## 측정 기록

| 구분 | 남길 값 |
|---|---|
| 입력 조건 | 몬스터 ID, 개체 레벨, 플레이어 스탯, 커맨드 번호, 공식 변수 |
| 진행 기록 | 예약과 실행 행동, 적 패턴, 커맨드 성공 시점, 긴급 행동 사용 |
| 종료 결과 | 전투 시간, 승패, 양측 수명 소모, 흡수량, 수명 손익 |
| 조정 기록 | 변경한 값, 변경 이유, 재비교할 조건 |

# 3.2 구현 차이와 수치 기준

## 기획과 현재 시뮬레이터

| 항목 | 기획 기준 | 현재 시뮬레이터 |
|---|---|---|
| 약점 파악 2회 | 첫 슬롯 자동 예약 | 현재는 첫 공격 표시만 수행 |
| 커맨드 전환 | Elite 2개, Boss 3개 순차 | 현재는 선택한 커맨드 번호로 고정 |
| 성공 로그 | 성공 시 ×5, 이력 재사용 범위 결정 필요 | 성공 이력이 남아 있는 동안 이후 공격에도 ×5 적용 |
| 행동 예약 변경 | 실행 전 예약 변경 가능 | 빈 슬롯 채우기만 가능, 변경 미구현 |
| 긴급 행동 시점 | 양측 1회 행동 이후 | 시작 직후부터 사용 가능, 시점 제한 미구현 |
| 긴급 행동 종류 | 약점 파악, 즉시 방어, 회복, 후퇴 | 약점 파악과 회복만 구현 |
| 약점 파악 비용 | 사용 횟수별 수명 비용 증가 | 회당 WEAK_COST 고정, 기본값 10 |
| 상태이상 | 지속 턴, 갱신, 중첩 규칙 | 미구현, 해당 패턴은 피해 배율과 이름만 표시 |

## 수치 기준 정리

팀원이 작성한 수명 기준 문서와 회의록, 전투 시스템 기획서 사이의 차이를 정리한다.

| 불일치 | 정리할 기준 |
|---|---|
| 전투 소모가 문서별 1초당 1일 / 10일 | LIFE_DECAY 기준 하나로 통일 |
| 약점 파악 비용 −8일 / −10 LF | 비용 단위와 사용 횟수별 증가 규칙 확정 |
| 후퇴 비용 0일 / −20일 | 후퇴 시 손실과 패배 처리를 함께 확정 |
| 붉은 처형인 1065일, 엘리트 기준 상한 1000일 | 개별 예외인지 테이블 수정 대상인지 결정 |

우선 수명 소모와 비용 기준을 통일한 뒤 동일 조건 비교를 진행한다. 측정값과 변경 이유를 함께 기록하고, 채택한 값을 기획서와 테이블에 반영한다.
