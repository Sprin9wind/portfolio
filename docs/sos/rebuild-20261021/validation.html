검증_비교 조건과 수명 손익

검증할 가설: 약점을 빠르게 알아내 처치한 전투가, 무작위 공격을 반복한 전투보다 수명 손익이 좋아야 한다.

같은 조건에서 한 가지 차이를 비교

고정할 조건 비교할 조건 기록할 결과
같은 몬스터, 레벨, 플레이어 스탯 커맨드 미공략 / 공략 처치 시간, 행동 횟수, 수명 손익
같은 커맨드, 공격력, 방어력 ATBSpeed 충전 시간과 시간 비용
같은 몬스터, 커맨드, 스탯 약점 파악 미사용 / 사용 힌트 비용과 처치 시간 단축분
같은 등급, 레벨, 커맨드 상태이상 유무 행동 지연과 누적 피해, 구현 후 비교

손익을 읽는 기준

수명 손익 = 실제 흡수량 − 시간 소모 − 긴급 행동 비용같은 수명 단위로 환산한다. 비용이 포함된 총소모를 썼다면 긴급 비용을 다시 빼지 않는다.

계산 예시: 승리하여 100을 흡수하고 시간에 20, 힌트에 10을 썼다면 손익은 +70이다. 이 숫자는 계산 설명을 위한 예시이며 플레이 측정 결과가 아니다.

현재 결과 패널의 한계, gained = max(0, 남은 몬스터 수명)을 승패와 무관하게 계산한다. 패배해도 흡수량이 표시될 수 있으므로 패배의 흡수량, 손익을 유효한 보상으로 집계하지 않는다. 플레이어 총소모에는 이미 긴급 행동 비용이 포함된다.

측정 전에 통과할 조건

  1. 엑셀의 열과 행이 올바르게 로드되는지, 원본 표와 화면 수치를 대조한다.
  2. 수명 단위, 소모율, 긴급 비용과 성공 로그의 재사용 범위를 정한다.
  3. 승패별 보상 계산을 분리하고, 미구현 규칙은 비교 대상에서 제외한다.
  4. 무작위 패턴의 선택 이력과 반복 횟수를 기록한다. 현재 난수 시드 고정 기능은 없다.

남길 기록

몬스터 ID, 레벨, 스탯, 커맨드, 공식 변수 → 예약, 실행 행동, 적 패턴, 성공 시점 → 승패, 전투 시간, 양측 소모, 실제 흡수, 손익 순서로 기록한다. 등급별 목표 전투 시간, 합격 수치, 반복 횟수는 아직 정하지 않았다.

연결된 데이터의 범위

현재 시뮬레이터는 MonsterTB의 스탯, 커맨드, 패턴 이름과 효과 코드를 읽는다. 공격 패턴, 상태이상, 드롭 시트 전체를 실행하는 도구는 아니다. 예를 들어 목패 포졸의 레벨 1 값은 HP 100, ATK 15, DEF 4, 수명 375다. 표의 값이 연결되어도 모든 효과의 동작까지 검증된 것은 아니다.

불일치 남은 결정

후퇴 0일 / −20일 후퇴 비용과 패배 손실을 함께 확정
붉은 처형인 1065일 / Elite 상한 1000일 개체 예외인지, 기준 또는 테이블 수정 대상인지 결정
검증 범위, 수식 계산과 코드의 동작 확인은 가능하지만, 밸런스 개선이나 재미 검증이 끝났다는 뜻은 아니다. 먼저 데이터 로딩과 기획 기준을 맞추고, 같은 조건의 반복 측정으로 채택할 값을 결정한다.
