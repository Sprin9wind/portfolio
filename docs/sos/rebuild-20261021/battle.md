# 전투_시간을 쓰며 약점을 찾는 ATB
<p class="lead">적의 남은 수명을 빼앗아 살아남는다. 공격 순서를 알아내는 동안에도 양쪽의 수명이 줄어, 빠른 처치가 다음 탐험에 쓸 자원으로 이어진다.</p>

## ● ATB는 무엇인가

**ATB(Active Time Battle)는 시간이 흐르면 행동 게이지가 차고, 가득 찬 쪽이 행동하는 전투 방식이다.** SOS에서는 각자의 게이지가 100%에 도달하면 예약한 행동을 실행한다. 행동은 한쪽이 끝난 뒤 다음 행동을 처리한다.

## ● 왜 이 방식인가

수명은 생존 시간인 동시에 탐험과 거래에 쓰는 자원이다. 전투에 실시간 소모를 두면 **고민하는 시간도 비용**이 된다. 전투 밖에서는 행동 단위로 소모하도록 구분해, 모든 상황에서 실시간으로 수명이 줄어드는 부담을 피하는 방향으로 정했다.

<div class="flow" aria-label="전투 반복 흐름"><div><b>충전, 예약</b><span>양측 ATB 증가<br>양측 수명 감소</span></div><i>→</i><div><b>100% 도달</b><span>예약 행동 실행<br>피해와 생존 판정</span></div><i>→</i><div><b>단서 확인</b><span>공격 로그, 피해 표시<br>다음 행동 선택</span></div></div>
<p class="loop">전투가 끝나지 않았다면 충전과 예약을 반복한다. 기획상 4개 슬롯이 모두 활성화된 뒤 입력을 기다릴 때는 플레이어의 수명 소모를 멈춘다.</p>

## ● 플레이어가 판단할 것

| 선택 | 얻는 것 | 지불하거나 감수하는 것 |
|---|---|---|
| 직접 공격하며 추리 | 공격 종류와 순서의 단서 | 추리에 걸리는 시간과 피격 위험 |
| 약점 파악 사용 | 커맨드 길이 또는 첫 공격의 실마리 | 긴급 행동의 수명 비용 |
| 방어, 회피 예약 | 적 공격에 대응할 기회 | 해당 행동 기회에 공격하지 않음 |

## ● 진입과 종료

탐험 중 적 타일에 1칸 이내로 인접하면 전투에 진입한다. **적 HP 0 → 남은 적 수명 흡수**, **플레이어 HP 0 → 전투 패배**, **플레이어 수명 0 → 런 종료**로 구분한다. 패배 시 손실 규칙은 확정이 필요하다.

## ● 입력과 기록의 역할

| 영역 | 기획 규칙 | 플레이 중 읽는 방법 |
|---|---|---|
| 기본 행동 | 공격 1, 2, 3, 방어, 회피 | 공격 종류를 바꾸며 약점 순서를 추리 |
| 행동 예약 | 슬롯 4개, 실행 전 변경 가능 | 앞으로 실행할 행동을 미리 구성 |
| 공격 로그 | 공격만 최대 13개, 오래된 것부터 제거 | 이미 실행한 공격에서 순서를 찾음 |
| 긴급 행동 | 수명 비용 표시, ATB와 무관하게 실행 | 시간을 기다리는 대신 수명을 지불 |

<div class="inline-example"><b>예약 예시</b><span>공격 2</span><span>공격 1</span><span>공격 3</span><span>방어</span><em>실행 전의 선택</em></div>

기획상 충전이 끝난 슬롯은 활성 상태로 남는다. 이때 행동을 고르면 가장 오래된 활성 슬롯에서 즉시 실행한다. **4개 모두 활성화된 채 입력을 기다리면 플레이어 수명 소모를 멈추지만**, 현재 시뮬레이터는 계속 소모한다.

## ● 긴급 행동의 사용 조건

**플레이어와 적이 한 번씩 행동한 뒤 활성화**하는 기획이다. 약점 파악, 즉시 방어, 체력 회복, 후퇴를 구성하며, 후퇴는 패배로 처리한다. 회복은 회복량에 비례해 수명을 소모하는 방향이며 비용 기준은 검증 문서에서 별도로 다룬다.

<div class="note"><b>현재 시뮬레이터</b>는 빈 예약 슬롯 채우기와 약점 파악, 회복만 제공한다. 예약 변경과 긴급 행동의 시점 제한, 즉시 방어, 후퇴는 구현되어 있지 않다. 위 팀 UI 시안은 현재 시뮬레이터 화면과 구분한다.</div>

# 전투_ATB 속도와 피해 계산
## ● 현재 시뮬레이터의 충전 시간과 수명 소모

<div class="formula">T = 1000 ÷ (100 + ATBSpeed ÷ 5)<small>T: 충전 시간(초), 충전 중 수명 소모 = T × LIFE_DECAY</small></div>

속도가 높아지면 한 번 행동하기까지의 대기와 그동안의 수명 소모가 줄어든다. **ATBSpeed 500에서 정확히 5초**이며, 5초를 공식의 최솟값으로 뜻하지 않는다.

| ATBSpeed | 0 | 100 | 300 | 500 |
|---|---|---|---|---|
| 충전 시간(초) | 10.00 | 8.33 | 6.25 | 5.00 |
| 수명 소모(LIFE_DECAY = 1) | 10.00 | 8.33 | 6.25 | 5.00 |

표는 연속 시간 공식의 계산 예시다. 현재 시뮬레이터는 0.2초 간격으로 갱신하므로 실제 행동 시각과 소수 표시를 구분한다. 수명 단위와 소모율은 문서 간 불일치가 있어 통일 전이다.

## ● 현재 시뮬레이터의 기본 피해와 약점 보상

| 판정 | 계산 | 공격력 30, DEF 20인 예시 |
|---|---|---|
| 기본 피해 B | max(1, floor(공격력 × 100 ÷ (100 + DEF))) | B = 25 |
| 약점 후보 공격 | floor(B × 1.1) | 27 |
| 커맨드 성공 공격 | floor(B × 5), ×1.1과 중첩하지 않음 | 125 |

floor는 소수점 버림이다. 위 식은 현재 시뮬레이터 기본값이다. **전투 기획서의 공격력−방어력, 성공 ×2와 구분**하며, 두 계산을 섞지 않는다. 공격 1, 2, 3의 기본 피해는 같게 두어 공격 종류와 순서에 집중하도록 한다.

## ● 방어와 회피

- 방어는 피해 계산에 사용하는 **DEF를 2배**로 적용한다. 위 조건이라면 30 × 100 ÷ 140의 소수점을 버려 피해는 21이다.
- 회피 확률은 **50%**를 기준으로 둔다. PowerAtk는 방어 행동의 효과를 무시하며, 기본 DEF까지 0으로 만드는 뜻은 아니다.
- 기획상 같은 방어, 회피는 중복 예약하지 않고, 적 공격 1회에 먼저 사용한 대응 행동을 처리한다. 현재 구현은 예약 중복을 막지 않으며 회피 준비를 먼저 확인한다.

# 전투_약점 커맨드와 추리 피드백
공격 1, 2, 3을 중복 허용하여 **2~4자리**로 조합한다. 가능한 조합은 3² + 3³ + 3⁴ = **117개**이며, 몬스터별 커맨드는 기획자가 지정한다. 방어, 회피, 긴급 행동은 공격 로그에 넣지 않는다.

## ● 순서는 유지하되, 연속할 필요는 없다

<div class="command"><div class="command-row"><b>목표 커맨드</b><span class="hit">2</span><span class="hit">1</span><span class="hit">3</span></div><div class="command-row"><b>공격 로그 예시</b><span class="hit">2</span><span class="skip">2</span><span class="hit">1</span><span class="skip">1</span><span class="hit">3</span><strong>성공</strong></div><p>강조한 2 → 1 → 3을 순서대로 고를 수 있다. 사이의 다른 공격은 건너뛴다.</p></div>

현재 판정은 최대 13개 로그 안에서 순서를 지키는 **부분 수열**을 찾는다. 예를 들어 3 → 1 → 2만 있으면 2 → 1 → 3의 순서를 만들 수 없으므로 실패한다.

## ● 정답 대신 주는 단서

| 상태 | 현재 시뮬레이터 피해 | 기획상 시각 피드백 |
|---|---|---|
| 일반 | B | 노란색 숫자 #FFD900 |
| 해당 공격이 커맨드에 포함 | floor(B × 1.1) | 붉은 계열 #FF6161 |
| 순서 조건 성공 | floor(B × 5) | 빨간색 #FF0000, 글자 크기 65, 성공 로그 강조 |

피해 배율은 현재 시뮬레이터의 기본값이며, 색, 글자 크기, 강조는 기획상 표시 기준이다. 약점 후보 표시는 해당 공격이 **몇 번째 자리인지**까지 공개하지 않는다.

## ● 약점 파악과 남은 판정 결정

약점 파악은 최대 2회다. **1회는 커맨드 길이**, **2회는 첫 슬롯에 정답 공격 자동 예약**이 기획 기준이다. 현재 시뮬레이터의 2회 보상은 첫 공격 이름 표시까지다.

<div class="note"><b>성공 이력 재사용</b>, 현재 구현은 성공한 로그를 소비하지 않는다. 위 로그 뒤에 다른 공격을 추가해도 성공 수열이 남아 있으면 다시 ×5가 적용된다. 반복 보상을 어느 범위까지 허용할지 정한 뒤 공략 효과를 비교해야 한다.</div>
